## 1. 执行纪律

每个 Phase 开始前：

1. 阅读产品文档、`docs/PHASE_STATUS.md` 和仓库内 `AGENTS.md`。
2. 检查工作区已有改动，不覆盖用户文件。
3. 明确本 Phase 范围、依赖和验收命令。
4. 若实现需要改变业务规则，先停止并提出文档变更，不自行猜测。

每个 Phase 结束时必须交付，并把状态 `todo` → `done`：

- 已完成项与未完成项；
- 变更文件摘要；
- 自动测试、手工验证及结果；
- 数据迁移或兼容性说明；
- 已知风险 / 遗留问题；
- 下一 Phase 的输入条件。

上述内容写入 [PHASE_STATUS.md](./PHASE_STATUS.md) 的关闭记录，并同步本文件该 Phase 标题、PRD/数据模型/规则的实现状态。禁止只改代码不改文档状态。

禁止“一次性把整个系统做完”。核心引擎在通过独立测试前不得接入最终自动排班按钮。

## Phase 0：项目骨架与持久化探针 【done】

### 目标

建立 Tauri 2 + React + TypeScript + Vite + SQLite 的最小可运行项目，优先证明本地持久化可靠。

### 任务

- 初始化 Tauri 2、React、TypeScript strict、Vite。
- 选择并锁定与 Tauri 2 兼容的 SQLite 接入方式。
- 建立迁移机制、仓储接口、错误处理和测试框架。
- 做一个仅供开发验证的持久化探针：写入记录、关闭应用、重开读取。
- 配置格式检查、类型检查、单元测试和 Mac 构建命令。
- 编写 README：开发、测试、数据库位置和迁移方法。

### 不做

教师、日历、排班 UI 和算法。

### 验收

- Mac 上应用启动无错误。
- 探针数据在重启后存在。
- 空数据库可自动迁移到最新版；重复启动不重复迁移。
- 类型检查、测试、构建全部通过。

### 状态

**done**（2026-09-02）。关闭记录见 [PHASE_STATUS.md](./PHASE_STATUS.md#phase-0-关闭记录done)。

完成项：Tauri 2 骨架、`rusqlite` 迁移、探针仓储、macOS 构建。测试：`typecheck` / Vitest 2 / cargo test 4 / `tauri build` 均通过；重启后探针行仍在。遗留：导出模版 xlsx 缺失；`probe_events` 非业务表。

## Phase 4：纯 TypeScript 排班引擎 【todo】

### 目标

在不接 UI、不直连数据库的前提下，完成可复现、可解释的核心引擎。

### 任务

- 定义版本化输入/输出 DTO。
- 实现资格筛选、空缺构建、可行性估算。
- 实现月度最低负担层与第二/第三轮。
- 实现特殊返校最低层、楼层 ±1、学期累计、间隔和稳定决胜。
- 实现相邻日放宽、空缺保留、警告与解释快照。
- 实现确定性空缺顺序与输入指纹。
- 建立固定夹具和表驱动测试。

### 必测用例

完整实现 `BUSINESS_RULES.md` BR-T01–BR-T15，并增加：

- 不同输入顺序产生相同规范结果；
- 跨月最近值班日与相邻日；
- 多个固定任务导致的第三轮；
- 全部本楼层教师被排除；
- 人工固定岗位绝不被修改；
- 无解时输出空缺及阻断错误，而非抛出未处理异常。

### 验收

- 引擎无 UI、SQLite、文件系统依赖。
- 所有规则测试通过；相同输入重复 100 次结果一致。
- 每个自动分配都有完整 `AssignmentExplanation`。
- 可行性结果包含预计轮次与容量说明。

## 4. 全局完成定义（Definition of Done）

一个任务只有同时满足以下条件才算完成：

- 行为与规则编号一致，没有用 UI 文案替代业务校验；
- 新增逻辑有自动测试，核心算法有反例测试；
- 数据变更有迁移和回滚/恢复说明；
- 错误对用户可理解且不损坏已有数据；
- 类型检查、测试、构建通过；
- 相关文档同步更新（至少 TASKS、PHASE_STATUS，以及本 Phase 触及的 PRD / 数据模型 / 规则）；
- 该 Phase 在 PHASE_STATUS 中从 `todo` 改为 `done`，关闭记录含完成项、测试结果、改动文件、文档更新、遗留问题；
- 没有把用户提供的真实教师数据提交到公开仓库或测试快照。
