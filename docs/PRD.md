> 关联文档：[BUSINESS_RULES.md](./BUSINESS_RULES.md)、[DATA_MODEL.md](./DATA_MODEL.md)、[TASKS.md](./TASKS.md)、[PHASE_STATUS.md](./PHASE_STATUS.md)

## 1. 产品概述

财会系值班排班系统是一款供系部排班管理员使用的本地桌面工具。它将教师名单、学校已确定的固定任务、系部值班日期与历史公平统计统一到一个可解释的排班流程中，自动补齐普通岗位，允许人工调整，并输出可使用的 Excel 排班表。

产品不是多用户信息化平台，而是：

> 排班计算器 + 可视化编辑器 + 历史值班账本。

## 2. 背景与问题

人工排班需要同时考虑月度轮转、学期累计、大值班、特殊返校日、楼层、临时排除和连续值班，容易遗漏固定任务或产生不易解释的不公平。现有 Excel 适合传阅，但不适合持续保存规则、跨月判断和重新计算统计。

本产品要解决：

- 固定任务与自动排班脱节；
- 月度容量不足时缺少明确的第二轮机制；
- 月初特殊返校日需要跨月判断；
- 历史调整后统计容易失真；
- 自动结果缺少“为什么是这位老师”的解释；
- 数据长期依赖散落的 Excel 文件。

## 3. 目标与非目标

### 3.1 MVP 目标

1. 在 macOS 上完成可持续使用的本地应用，并为后续 Windows 打包保留同一代码库。
2. 支持教师、学期、月排班、固定任务和历史账本的 SQLite 持久化。
3. 正确实现 `BUSINESS_RULES.md` R001–R050，尤其是第二轮、跨月特殊返校、大值班和人工调整。
4. 自动结果稳定可复现、可解释，并在生成前后展示容量与冲突。
5. 支持从三 Sheet 教师名单导入，支持按模板导出排班结果，以及系统备份/恢复。
6. UI 简约清晰，新用户能按步骤完成一个月排班。

### 3.2 非目标

- 不做账号、权限、多用户协作和云同步。
- 不做服务器、在线数据库或学校网络部署。
- MVP 不接入在线节假日 API。
- 不做复杂拖拽动画、高保真视觉或移动端。
- 不做完整排班版本历史、审批流和电子签名。
- 不保证纯数学全局最优；优先保证规则正确、结果稳定和可解释。

## 4. 用户与核心流程

### 4.1 用户

主要用户为财会系排班管理员，通常由一至两位教师在固定电脑上操作。用户不应需要理解数据库、命令行或算法细节。

### 4.2 月度排班主流程

```text
选择/创建学期
→ 导入或维护教师名单
→ 创建月份并选择系部值班日期
→ 确认系统识别的特殊返校日
→ 设置本月排除人员
→ 录入大值班及其他人工固定任务
→ 查看排班前可行性检查
→ 自动补齐普通岗位
→ 查看统计、解释和警告
→ 人工换人/调整（不自动洗牌）
→ 确认月份
→ 导出 Excel / 备份
```

## 5. 功能需求

### F01 学期管理

- 新建学期，设置名称、开始和结束日期。
- 选择当前工作学期，关闭/重新打开学期。
- 学期之间历史与公平统计隔离。
- 学期关闭前提示未确认月份。

验收：可创建合法学期；重叠或非法日期被阻止；关闭后默认只读。

### F02 教师管理

- 查看、搜索、新增、编辑、停用、恢复教师。
- 按学期设置楼层组、是否大值班、是否参与及初始公平次数。
- 停用不删除历史。
- 同时展示实际学期次数与有效公平次数。

验收：符合 R001–R008；重名不导致数据串联；初始公平次数不产生虚假记录。

### F03 Excel 教师导入

- 支持三 Sheet：1–3 楼、4–5 楼、大值班。
- 提供列/Sheet 映射、预览、重复与错误提示。
- 大值班名单作为标签合并到楼层教师，不创建第三类教师。
- 用户确认后一次性导入。

验收：失败不留下部分数据；大值班缺少楼层时必须人工解决；导入后不依赖原文件运行。

### F04 月份与值班日历

- 创建学期内月份，以月历选择系部值班日。
- 每个系部值班日可设为普通日或集中值班日。
- 系统依据相邻自然日自动识别连续周期和特殊返校日。
- 月初跨月查询；历史不足时要求人工确认。
- 允许人工取消/补充特殊返校标记。

验收：符合 R009–R014，跨月用例通过；周几和节假日不影响核心判定。

### F05 月度排除

- 在自动排班前勾选本月不参与自动排班的教师，可填自由文本原因。
- 下月不继承；教师仍可被人工安排。

验收：被排除者不会自动出现；人工安排时提示但允许保存；后续月份公平排序自然补偿。

### F06 人工固定排班

- 在日期上搜索并添加教师，选择任务类型。
- 支持大值班、班主任集中值班、开学/期末、领导、其他。
- 大值班日期是普通系部日时默认占教师所属楼层岗位；非系部日时只记账、不占岗位。
- 集中值班日人数不限，不生成普通岗位。
- 人工安排默认锁定，自动生成不得覆盖。

验收：符合 R015–R022；任何人工实际值班正确计入月度、学期和特殊返校统计。

### F07 排班前可行性检查

- 自动生成前显示总岗位、已填、剩余、排除人数、各楼层候选量、尚未值班人数。
- 估算至少使用到第几轮，并解释进入第二轮的原因。
- 对无候选、缺少跨月依据等情况给出阻断提示。

验收：示例中的剩余岗位和最低轮次计算正确；估算与实际不同能按 R050 解释。

### F08 自动排班引擎

- 纯 TypeScript 实现，不依赖 UI 或数据库，可用固定输入独立测试。
- 输入教师快照、历史账本、日期、固定任务、排除项；输出分配、统计、解释和警告。
- 遵循 R025–R037，包括月度最低负担层、特殊返校轮转、楼层 ±1、相邻日放宽、稳定决胜。
- 无法填满时保留空缺，不伪造结果。

验收：`BUSINESS_RULES.md` 第 6 节全部用例通过；同输入多次运行结果一致。

### F09 结果查看与解释

- 月历/列表显示每天岗位、人员、任务标签和来源。
- 侧栏显示个人本月次数、实际学期次数、有效公平次数、特殊返校次数、历次日期。
- 点击自动安排显示决策解释。
- 集中显示可定位的错误、警告和信息提示。

验收：解释至少覆盖 R046；点击警告可定位到日期或教师；实际与公平口径名称清楚。

### F10 人工调整

- 草稿中支持换人、添加、删除和移动。
- 每次调整只改变目标，不自动重排剩余月份。
- 实时刷新统计、空缺和警告。
- “补齐空缺”和“重新自动排班”为两个显式操作；后者保留人工任务、重建自动任务。

验收：调整一个岗位后其他自动岗位的 ID 与人员均不变；重新生成前有确认提示。

### F11 草稿与已确认

- 新月份默认草稿。
- 有空缺或错误时禁止确认；警告需用户知情确认。
- 已确认月份只读，可撤回草稿后编辑并再次确认。
- 历史月份允许按上述流程修改，MVP 不提供完整版本对比。

验收：符合 R042–R045；状态切换和修改在事务中完成。

### F12 Excel 导出

- 将已确认排班导出为 `.xlsx`；如提供现有模板，应尽量保持模板结构和样式。
- 至少包含日期、星期、1–3 楼、4–5 楼、任务标签及必要备注；集中日可合并展示多人。
- 导出前预览文件名和保存位置。
- 导出失败不影响已保存数据。

验收：Excel 可正常打开，中文与日期无乱码，抽查内容与应用一致。

### F13 数据备份与恢复

- 用户可导出带版本信息的一致性备份。
- 恢复前校验并展示覆盖提示；失败保留原数据。
- 恢复后重新加载并执行完整性检查。

验收：在一台全新测试环境恢复后，教师、学期、日期、排班和状态一致。

## 6. 页面与交互

### 6.1 建议信息架构

1. **排班工作台**：主页面，左侧/月历约 2/3，右侧为当前步骤、教师、统计和提示。
2. **教师与学期**：教师表格、学期成员和 Excel 导入。
3. **历史与导出**：月份列表、状态、再次打开、导出。
4. **设置与备份**：备份、恢复、应用信息。

### 6.2 排班工作台

顶部显示学期、月份、草稿/已确认和步骤：

```text
1 选择日期 → 2 排除人员 → 3 固定安排 → 4 自动排班 → 5 检查确认
```

月历单元格应显示：日期、普通/集中、特殊返校标记、两楼层岗位或集中人员、人工/自动来源、警告标记。右栏在不同步骤切换候选教师、可行性、统计、解释和问题清单。

### 6.3 视觉原则

- 白/浅灰背景，一个主色；使用表格、卡片、徽标和简单弹窗。
- 不依赖颜色表达唯一信息；状态同时使用文字/图标。
- 危险操作给出明确对象和影响，不使用模糊的“确定吗”。
- 目标分辨率以常见 Mac/Windows 笔记本为主；关键操作无需横向滚动。

## 7. 技术方案

### 7.1 技术栈

```text
Tauri 2
├── React
├── TypeScript（strict）
├── Vite
├── SQLite（应用私有数据目录）
├── TypeScript 纯函数排班引擎
├── Excel 导入/导出库
└── Rust：桌面壳、本地文件与必要 Tauri 命令，业务逻辑尽量少
```

具体依赖已在 Phase 0 锁定，记录于 [PHASE_STATUS.md](./PHASE_STATUS.md) 与仓库 README。不得引入服务器、远程数据库或运行时网络依赖。

已锁定（Phase 0）：

```text
Tauri 2.11.5 / CLI 2.11.4 / JS API 2.11.1
React 19.2 / TypeScript 5.8 strict / Vite 7.3
SQLite：rusqlite 0.40.2 bundled（Rust 命令层，非 @tauri-apps/plugin-sql）
测试：Vitest 4、cargo test
```

### 7.2 分层

```text
React UI
  ↓ application services / Tauri commands
Repository 接口
  ├── SQLite 实现（rusqlite，应用数据目录 duty-roster.db）
  └── 测试内存实现

Schedule Engine（纯 TypeScript）
  输入 DTO → 规则计算 → 输出 DTO
```

排班引擎不得直接访问 SQLite、文件系统或 UI 状态。数据库迁移纳入版本控制。日期计算使用本地业务日期，避免时区转换把日期移到前一天。

### 7.3 平台策略

- 开发与首轮验收：macOS。
- Windows 发布：优先在 Windows 环境或 CI 构建并测试安装包。
- 两个平台使用同一业务代码与迁移；平台差异限于文件选择、路径和打包。

## 8. 非功能需求

### 8.1 可靠性

- 数据写入使用事务；外键开启；启动时执行迁移与轻量完整性检查。
- 统计应可从账本重建；不得仅依赖缓存累计。
- 自动生成使用输入指纹和稳定决胜，结果可复现。
- 关闭应用、异常退出后已完成事务的数据不丢失。

### 8.2 性能

以单系部规模（约 20–100 名教师、数年历史）为目标：普通页面交互小于 200ms；单月自动排班在常规设备上目标小于 2 秒；导入导出期间显示进度或忙碌状态。

### 8.3 可维护性

- TypeScript 开启 strict；核心规则具备单元测试。
- 数据迁移、警告代码和业务规则编号可追踪。
- 算法测试优先于 UI 快照测试。
- 关键用户流程有集成测试，Mac 构建通过后才进入 Windows 打包。

### 8.4 隐私与安全

数据默认仅保存在本机应用目录；不上传教师名单。备份和 Excel 由用户选择位置。错误日志不得无提示写入教师敏感备注。

## 9. MVP 总体验收

使用一份真实三 Sheet 教师名单、一个普通月份和一个含跨月/集中值班的特殊月份，完成以下端到端验收：

1. 导入教师，创建学期并设置一名教师初始公平次数。
2. 选择值班日期，正确跨月识别特殊返校日；无历史时要求确认。
3. 排除一名教师，录入落在系部日与非系部日的两种大值班，并录入集中值班。
4. 可行性检查正确预估轮次；自动排班填满所有可填普通岗位。
5. 自动结果符合规则、重复生成稳定、每条自动分配可解释。
6. 人工换人后其他岗位不变，统计和警告立即更新。
7. 有空缺时不能确认；补齐后确认并导出可打开的 Excel。
8. 关闭重开数据仍在；导出备份并在测试环境恢复成功。
9. macOS 安装包可运行；Windows 构建在对应环境完成基础安装与启动验证。

## 10. 用户提供的开发输入

- `reference/系部教师名单.xlsx`：含三个 Sheet 的真实或脱敏样例。
- `reference/排班导出模版.xlsx`：排班导出模版。当前仓库尚未找到该文件，Phase 7 前需补齐。
- 两个脱敏历史月份：一个普通月、一个含开学/期末或跨月连续周期的特殊月，用于算法验收。
  - `reference/财会金融系教师晚自习值班表（2025年11月）.xlsx`：普通月
  - `reference/财会金融系教师晚自习值班表（2026年4月）.xlsx`：跨月连续周期

上述文件缺失不阻止 Phase 0 和纯规则单元测试，但会阻止 Excel 映射与真实数据最终验收。
