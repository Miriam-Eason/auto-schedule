# 财会系值班排班系统：业务规则规格

> 文档版本：1.1  
> 状态：开发基线；规则正文未改。Phase 1 已实现并测试 R001–R004；Phase 2 已实现并测试 R009–R014，并落地 R042/R044 基础状态流；Phase 3 已实现并测试 R005–R008、R015–R024，并建立 R025 所需资格数据约束；自动候选筛选由 Phase 4 纯 TypeScript 引擎完成
> 关联文档：[PRD.md](./PRD.md)、[DATA_MODEL.md](./DATA_MODEL.md)、[TASKS.md](./TASKS.md)、[PHASE_STATUS.md](./PHASE_STATUS.md)

## 1. 文档目的

本文是排班引擎与人工编辑行为的唯一业务规则来源。实现、测试和验收出现歧义时，以本文为准；产品范围见 `PRD.md`，持久化结构见 `DATA_MODEL.md`，实施顺序见 `TASKS.md`。

系统的总原则是：

> 固定任务优先、月度最低负担层优先、特殊返校公平、楼层归属优先但允许有限跨楼层、学期长期均衡、管理员拥有最终决定权。

## 2. 统一术语

| 术语          | 定义                                                                               |
| ------------- | ---------------------------------------------------------------------------------- |
| 学期          | 一段连续统计周期，所有长期公平统计均限定在当前学期内。                             |
| 系部值班日    | 财会系需要安排值班的日期。                                                         |
| 普通值班日    | 采用“1–3 楼 1 人 + 4–5 楼 1 人”双岗位结构的系部值班日。                            |
| 集中值班日    | 开学、期末等不采用双岗位结构、由管理员人工指定任意人数的日期。                     |
| 特殊返校日    | 连续值班周期的首个值班日；系统默认识别，管理员可改写。它不是“集中值班日”的同义词。 |
| 人工固定排班  | 管理员预先录入的任务，包括大值班、班主任集中值班、开学/期末、领导安排及其他任务。  |
| 大值班        | 学校层面安排的固定值班；无论日期是否为系部值班日，均计入教师实际值班次数。         |
| 月度排除      | 某教师在指定月份不参加自动排班；不等于停用，也不禁止管理员人工安排。               |
| 第一轮/第二轮 | 当前月度值班次数最低为 0/1 的候选层。更一般地称“月度最低负担层”。                  |
| 初始公平次数  | 教师加入某学期时人为设置的公平基线，只参与公平排序，不伪造实际值班记录。           |
| 草稿/已确认   | 月排班的编辑中/已发布状态。状态语义见 R042–R045。                                  |

## 3. 约束与目标优先级

### 3.1 不可由自动排班违反的硬约束（P0）

1. 人工固定排班不得被自动排班覆盖、移动或删除。
2. 同一教师同一自然日只计一次实际值班，自动排班不得把其重复分配到两个岗位。
3. 普通值班日最终应恰好填满两个岗位：`LOWER`（1–3 楼）与 `UPPER`（4–5 楼）。
4. 集中值班日不生成普通双岗位，人员仅由管理员人工指定。
5. 停用教师、非当前学期成员、月度排除教师不得进入自动候选池。
6. 自动排班不得改变已确认月份；必须先回退为草稿。

### 3.2 可在无解时逐层放宽的强约束（P1）

1. 优先从本月值班次数最低的层选人，只有最低层无法填满剩余岗位时才进入下一层。
2. 自动排班强烈避免同一教师相邻自然日值班；无其他候选人时可突破并产生警告。
3. 特殊返校日优先选择本学期特殊返校次数最低的教师。

### 3.3 排序与优化目标（P2/P3）

1. 在楼层 `±1` 容差内优先本楼层。
2. 尽量降低教师的“有效学期累计次数”。
3. 尽量拉长距教师上次值班的间隔。
4. 完全同分时使用稳定、可复现的确定性排序。
5. 在不破坏更高优先级规则的前提下，使学期有效累计次数的 `max - min` 尽可能小；`≤ 1` 是理想目标而非硬保证。

## 4. 规则清单

### 4.1 教师、学期与统计

**R001 学期成员快照。** 教师是否参与排班、所属楼层、大值班身份和初始公平次数按学期保存。修改当前资料不得改写历史学期事实。

**R002 教师停用而非物理删除。** 停用教师不进入未来自动排班，但历史排班、统计和导出必须保留其姓名及当时属性。

**R003 楼层与大值班身份相互独立。** 每位教师必须属于 `LOWER` 或 `UPPER`；`isMajorDuty` 是附加标签，不是第三个互斥人员类别。

**R004 初始公平次数。** 新增或加入学期时允许设置非负整数 `initialFairnessCount`。有效学期累计次数定义为：

```text
effectiveSemesterCount = initialFairnessCount + 本学期实际值班日期数
```

界面和导出统计应同时展示“实际次数”和“公平口径次数”，不得把基线伪装成某天的值班记录。

**R005 实际值班按人日计数。** 同一教师同一日期即使带有多个业务标签，也只增加一次月度、学期实际值班次数；数据层应避免重复人日。

**R006 所有实际任务统一计数。** 普通值班、大值班、集中值班、开学/期末、领导安排和其他人工任务均计入月度及学期实际值班次数。

**R007 特殊返校统计。** 教师在被标记为特殊返校日的日期实际值班时，其学期特殊返校次数增加 1；无论任务来自人工还是自动均如此。

**R008 历史修改后重算。** 修改、添加或删除历史排班后，所有受影响的月度/学期统计与冲突提示必须由账本重新计算，不得用不可追溯的累加值直接修补。

### 4.2 日期、连续周期与特殊返校日

**R009 值班日期由管理员选择。** 周末、法定节假日只可作为视觉辅助，不作为是否值班或是否特殊返校的核心依据；MVP 不依赖在线节假日 API。

**R010 连续周期判定。** 对任一系部值班日 `D`：若前一自然日 `D-1` 也是系部值班日，则 `D` 延续原周期；否则 `D` 是新周期首日，并默认标记为特殊返校日。

**R011 跨月判断。** 月初首个值班日必须查询上一自然日，而不是只查询当前月。若 3 月 31 日和 4 月 1 日均为系部值班日，则 4 月 1 日不是新周期首日。

**R012 历史缺失。** 若系统没有足够历史数据判断本月首个值班日前一自然日是否为值班日，状态必须为“待确认”，不得擅自判定；管理员确认后保存明确结果。

**R013 人工改写。** 管理员可取消系统默认的特殊返校标记，也可补充标记其他日期。人工改写优先于自动推导，并记录 `specialReturnSource = MANUAL`。

**R014 日期类型独立。** `NORMAL`/`SPECIAL_MANUAL`（集中值班）决定岗位结构；`isSpecialReturn` 决定返校公平统计。二者可以任意组合，不得互相推断。

### 4.3 人工固定排班与大值班

**R015 人工优先。** 自动排班只补空缺岗位，绝不修改人工固定排班。人工任务默认锁定。

**R016 人工可突破。** 管理员可人工安排已月度排除、已值班或相邻日已值班的教师。系统应先给出具体影响和警告，但允许保存。

**R017 人工任务类型。** 至少支持 `BIG_DUTY`、`HEAD_TEACHER_GROUP`、`TERM_SPECIAL`、`LEADER`、`OTHER`；类型用于显示与分析，计数遵循 R005–R007。

**R018 大值班无条件占额度。** 大值班日期即使不是系部值班日，也写入值班账本并使当月、学期实际次数各增加 1。

**R019 大值班占系部岗位。** 若大值班日期也是普通系部值班日，则它占用该教师所属楼层岗位。例如 `LOWER` 教师的大值班填满 `LOWER`，自动排班只补 `UPPER`。

**R020 大值班不占岗位。** 若大值班日期不是系部值班日，则 `occupiesDepartmentSlot = false`，不创建系部岗位，但仍按 R018 计数。

**R021 集中值班。** 集中值班日不采用双岗位结构，人数不限且全部人工指定；自动排班不为该日补人。

**R022 普通日人工安排。** 在普通值班日人工放入某楼层教师时，相应岗位视为已填；如明确跨楼层安排，管理员必须选择其占用的目标岗位。

### 4.4 月度排除与资格

**R023 月度排除只影响自动候选。** 排除按“教师 + 年月”保存，到下月自动失效；教师仍可被人工安排，其历史与统计不受删除。

**R024 排除后的长期公平。** 不设计强制“补班”字段。教师后续因有效学期累计较低，会在正常公平排序中自然获得优先级。

**R025 自动候选资格。** 候选人必须同时满足：当前学期有效、教师未停用、未被本月排除、当天尚未值班、可承担目标岗位。

### 4.5 自动排班与第二轮机制

**R026 排班前检查。** 生成前必须显示：总岗位数、人工已填岗位、剩余岗位、本月排除人数、各楼层候选人数、本月尚未值班人数、预计至少需要进入的最高月度轮次，以及明显无解项。

**R027 月度最低负担层。** 对每个待填岗位，先计算所有合格候选人的本月实际值班次数，只保留最小值层。第一轮为 0 次，第二轮为 1 次，第三轮为 2 次，以此类推。第二轮不是异常，而是容量不足时的正式机制。

**R028 大值班参与轮次。** 已在非系部日期承担大值班的教师本月次数为 1，因此原则上不会在第一轮被安排；当 0 次层无法完成岗位时，仍可在第二轮被选中。

**R029 特殊返校最低层。** 对特殊返校日岗位，在月度最低负担层内，优先保留本学期特殊返校实际次数最少的候选人。所有人达到 1 次后自然从 1 次层继续轮转，不写死“最多 1 次”。

**R030 相邻日回避。** 在上述候选层中先排除前一日或后一日已有值班的教师；若因此无候选人，则恢复这些人并为最终安排产生 `ADJACENT_DUTY` 警告。

**R031 楼层 ±1 容差。** 在当前月度层（特殊返校日还需经过 R029）内，令 `globalMin` 为全部候选人的最低有效学期累计次数，`homeMin` 为目标楼层候选人的最低有效学期累计次数：

```text
若存在本楼层候选人，且 homeMin <= globalMin + 1：只在本楼层候选人中继续排序；
否则：允许跨楼层，在全部候选人中继续排序。
```

跨楼层安排必须记录原因，并产生信息提示；无本楼层候选人时可直接跨楼层。

**R032 学期公平排序。** 经 R031 得到候选集后，按有效学期累计次数升序排列。

**R033 间隔排序。** 学期累计相同时，距最近一次值班自然日更远者优先；从未值班者视为间隔无限大。

**R034 稳定决胜。** 仍同分时使用基于 `semesterId + yearMonth + 输入指纹 + teacherId + slotId` 的确定性哈希排序。相同输入重复生成必须得到相同结果，不使用不可复现的真随机。

**R035 空缺处理。** 所有层均无候选人时不得静默生成错误结果；保留空缺，产生阻断级警告并说明无候选原因。

**R036 生成顺序。** 自动引擎以确定性顺序处理空缺：特殊返校岗位优先；其后候选人数较少的岗位优先；再按日期、`LOWER`、`UPPER` 排序。每次落位后立即更新内存账本，再处理下一个岗位。

**R037 重新生成。** “重新自动排班”保留全部人工固定排班，删除并重建当前月的自动排班。操作前必须提示影响；相同输入应依据 R034 复现相同结果。

### 4.6 人工调整、状态与保存

**R038 调整不联动洗牌。** 自动生成后人工换人、添加、删除或移动时，只修改目标记录，并实时重算统计、空缺与警告；不得自动重排本月其他岗位。

**R039 换人影响。** `A → B` 后立即撤销 A 对该日期的计数、加入 B 的计数，并刷新两人的月度、学期、特殊返校统计及全月公平差。

**R040 自动补空缺需显式触发。** 人工删除造成空缺时，系统只提示。只有用户点击“补齐空缺”或“重新自动排班”才运行引擎。

**R041 保存原子性。** 一次人工操作、生成或状态切换必须在单个事务中保存；失败时不得留下半份结果。

**R042 新月份为草稿。** 创建的月排班初始状态为 `DRAFT`，可选择日期、录入固定任务、自动排班和人工调整。

**R043 确认条件。** 存在普通岗位空缺或阻断级错误时不得确认为 `CONFIRMED`；黄色警告可在用户明确知情后确认。

**R044 已确认只读。** 已确认月份默认只读。需编辑时执行“撤回为草稿”，完成修改后再次确认；MVP 不要求完整版本历史，但保留更新时间。

**R045 历史可编辑。** 只要所属学期存在，历史月份可撤回为草稿并修改；统计必须依据 R008 重新计算。

### 4.7 解释与警告

**R046 每个自动结果可解释。** 至少展示：所处月度轮次、本月次数、特殊返校次数（适用时）、有效学期累计、楼层匹配/跨楼层原因、最近值班日与间隔、是否放宽相邻日约束。

**R047 警告分级。** `ERROR` 阻止确认；`WARNING` 允许确认但需明确知情；`INFO` 仅解释结果。

**R048 最低警告集合。** 必须检测：岗位空缺、同日重复、非活动教师、月度排除但被人工安排、教师本月多次、相邻日值班、特殊返校次数不均、跨楼层、确认后数据不完整、缺少跨月判断依据。

**R049 警告可定位。** 每条警告包含代码、严重度、日期、教师/岗位（如适用）、人类可读说明及建议动作。

**R050 可行性估算不是承诺。** 排班前“预计最高轮次”是基于当前固定任务和候选容量的下界；生成结果可能因楼层、相邻日等约束使用更高轮次，必须解释差异。

## 5. 排班引擎参考伪代码

```ts
function generateSchedule(input): Result {
  validateInput(input);
  ledger = buildLedger(input.history, input.manualAssignments);
  vacancies = buildVacancies(input.dutyDays, input.manualAssignments);
  vacancies.sort(bySpecialReturnThenScarcityThenDateAndFloor);

  for (const slot of vacancies) {
    let candidates = eligibleTeachers(slot, input).filter(
      (t) => !ledger.hasDutyOn(t.id, slot.date),
    );

    if (candidates.length === 0) {
      addError("NO_ELIGIBLE_CANDIDATE", slot);
      continue;
    }

    candidates = keepMinimum(candidates, (t) => ledger.monthCount(t.id));

    if (slot.isSpecialReturn) {
      candidates = keepMinimum(candidates, (t) => ledger.specialReturnCount(t.id));
    }

    const nonAdjacent = candidates.filter((t) => !ledger.hasAdjacentDuty(t.id, slot.date));
    if (nonAdjacent.length > 0) candidates = nonAdjacent;
    else markRelaxation("ADJACENT_DUTY");

    candidates = applyFloorTolerance(candidates, slot.floor, 1);
    candidates.sort(byEffectiveSemesterCountThenLongestGapThenStableHash);

    const selected = candidates[0];
    assign(selected, slot, { source: "AUTO", explanation: snapshotDecision() });
    ledger.add(selected, slot.date);
  }

  return { assignments, warnings, explanations, statistics: ledger.summary() };
}
```

## 7. 变更纪律

新增或修改业务逻辑时，必须：先更新本文的规则编号与测试，再更新 `DATA_MODEL.md`（如涉及持久化）、`PRD.md`（如影响用户行为）和 `TASKS.md`（如产生实施任务）。代码中的规则注释、测试名称和警告代码应引用对应的 `Rxxx`。
